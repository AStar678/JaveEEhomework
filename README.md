# 项目部署与功能验证指南

本文档旨在提供一套完整的操作流程，帮助验收人员从环境部署到业务功能演示，全方位验证本项目是否满足所有需求。

---

## 第一阶段：环境部署与启动

### 1. 基础设施准备
本项目依赖 MySQL、Redis 和 Consul。请确保以下服务已就绪：

*   **MySQL (8.0+)**:
    *   注意：请确认以下文件中的数据库密码与本地一致
        *   viewer-service/src/main/resources/application.yml                                                                                                                              
        *   finance-service/src/main/resources/application.yml                                                                                                                             
        *   analysis-service/src/main/resources/application.yml  
    *   请依次执行项目 `sql` 目录下的三个脚本，初始化数据库结构与预置数据：
        1.  `01_viewer_db.sql` (观众/打赏库)
        2.  `02_finance_db.sql` (财务库)
        3.  `03_analysis_db.sql` (分析库)
*   **Consul (注册中心)**:
    *   运行项目根目录下的 `start-consul.bat`。
    *   访问 `http://localhost:8500` 确认服务启动。
*   **Redis (缓存/分布式锁)**:
    *   运行项目根目录下的 `start-redis.bat`。

### 2. 微服务启动
请在 IDE 中按顺序启动以下四个 Spring Boot 应用：

1.  **ViewerApplication** (观众服务 - 端口 8081)
2.  **FinanceApplication** (财务服务 - 端口 8082)
3.  **AnalysisApplication** (经营分析服务 - 端口 8083)
4.  **SimulationApplication** (模拟服务 - 端口 8084)

**验证标准**：访问 Consul (`http://localhost:8500`)，确认上述 4 个服务均显示为绿色 (Passing)。

## 第二阶段：功能验证流程

本项目提供了全套可视化前端 (`frontend` 目录)，请直接在浏览器中打开对应的 HTML 文件进行验证。

### 场景一：高并发模拟打赏

**操作步骤**：
1.  打开 `frontend/admin.html` (运营监控端)。
2.  在顶部的“压力测试控制台”中，设置线程数（例如 `20` 或 `50`）。
3.  点击 **“启动模拟”** 按钮。

**验证点**：
*   **前端反馈**：状态变为绿色“运行中”。
*   **后端日志**：查看 `logs/simulation-service/app.log`，应每秒打印 QPS 日志（如 `QPS: 600`），证明满足“每秒至少500次请求”的性能需求。
*   **数据流转**：查看 `logs/viewer-service/app.log`，应有大量“打赏入库成功”日志。

---

### 场景二：观众端体验与自动注册

> **注意**：数据分析及财务功能的调用并非实时同步，而是通过定时任务触发。当前默认的 ETL 和同步间隔已配置为 **1分钟**。如需调整，请修改 `analysis-service` 的 `application.yml` 配置文件。

**操作步骤**：
1.  打开 `frontend/viewer.html` (观众端)。
2.  **模拟打赏**：
    *   输入主播ID：`1`。
    *   输入**一个新的观众姓名**（如“小明”），**无需输入ID**。
    *   点击“发送打赏”。
    *   **验证**：提示“打赏处理成功”，说明系统自动完成了新用户的注册和ID生成。
3.  **查询个人标签**：
    *   在“我的标签”区域，输入刚才的姓名“小明”。
    *   点击查询。
    *   **验证**：显示“普通观众”或具体标签（如“High Spender”），证明 Viewer 服务成功通过 Feign 调用了 Analysis 服务。
    *   *(注：如果是新用户，可能需要等待约1分钟 ETL 任务运行后才能查到标签)*
4.  **查询主播榜单**：
    *   在“主播 Top10”区域，输入主播ID `1`。
    *   **验证**：列表展示该主播打赏金额最高的前10名观众，证明 Redis 分布式锁和聚合计算功能正常。

---

### 场景三：实时监控与数据可视化

**操作步骤**：
1.  回到 `frontend/admin.html`。
2.  **查看聚合报表**：
    *   切换到 **“聚合报表 (分钟级)”** Tab。
    *   点击“查询数据”。
    *   **验证**：
        *   **折线图**：展示了打赏金额随时间的动态走势，支持拖动缩放查看全量数据。
        *   **表格**：展示了按分钟、主播、性别聚合的详细数据，支持分页。
3.  **查看观众画像**：
    *   切换到 **“观众画像分布”** Tab。
    *   点击“刷新”。
    *   **验证**：展示饼图，直观显示 High/Medium/Low Spender 的人数占比。
4.  **查看明细流水**：
    *   切换到 **“打赏明细流水”** Tab。
    *   **验证**：可以看到每一笔具体的打赏记录，包含自动生成的 TraceId 和同步状态。

---

### 场景四：财务结算与动态分成

**操作步骤**：
1.  在 `admin.html` 中切换到 **“主播财务管理”** Tab。
2.  **查询初始状态**：
    *   输入主播ID `1`，点击“查询”。
    *   记录当前的“累计分成”金额（假设分成比例为 0.5）。
3.  **修改分成比例**：
    *   在右侧“分成比例设置”中，输入主播ID `1`，点击“查询比例”。
    *   将比例从 `0.5` 修改为 `0.8`，点击 **“更新比例”**。
    *   **验证**：提示“更新成功，已重新计算历史分成”。
4.  **验证重算结果**：
    *   再次点击左侧的“查询”余额。
    *   **验证**：可以看到“累计分成”瞬间大幅增加（变为总流水的 80%），证明系统支持动态调整比例并追溯历史数据。
5.  **提现**：
    *   输入提现金额（如 `100`），点击“提现”。
    *   **验证**：“已提现”金额增加，“可提现”余额减少。

---

### 场景五：服务容错与降级

**操作步骤**：
1.  在 IDE 中手动**停止 AnalysisApplication** 服务。
2.  回到 `frontend/viewer.html`。
3.  再次点击“查询”个人标签。

**验证点**：
*   页面**不会报错**或卡死。
*   标签区域显示 **“未查询到个人标签 (服务降级)”**。
*   证明 Resilience4j 断路器生效，非核心服务故障不影响核心业务。
